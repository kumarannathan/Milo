Playbooks

Two playbooks. Pick one on first run.

A playbook is a team of agents that pass work to each other through a task queue. Each agent has one job, its own schedule and its own model.

How it works

Nothing is sent or traded until you approve it.

Drafts arrive in Approvals with the facts behind them: the research brief, its sources and the lead score. Approve, edit, or reject with a note. The writer reads your note before its next draft.

Autonomy levels

Set per team. Change it any time in Settings.

Sales development
  • Review sends only Default

    Research, scoring and CRM updates run on their own. Every email, reply and invite waits for you.

  • Review first touches

    You approve the first email to each person. Follow-ups and replies go out on their own.

  • Autopilot

    Nothing waits for review. Escalations still come to you.

Markets
  • Review trades Default

    Agents research and propose. Every trade waits for you.

  • Autopilot

    Trader opens and closes paper positions on its own, within your limits.

Per-agent control

See every run, every call and what it cost.

Each run records its duration, tokens in and out, and cost. Each tool call records the operation, status code and latency. If a vendor rejects a key, the agent stops and holds its work until you reconnect.

Quickstart

Running in three commands.

You need Node 20 or later and git. Milo runs as one Node process and keeps its data in data/milo.json inside the project folder.

  1. 1

    Clone the repository

    git clone https://github.com/kumarannathan/milo.git
  2. 2

    Install dependencies

    cd milo && npm install
  3. 3

    Start Milo

    npm start

    Open http://localhost:4400. Pick a playbook, then add your keys or turn on sample data.

Optional settings

Set these in .env or your shell.

MILO_PORT
Port to listen on. Default 4400.
MILO_HOST
Address to bind. Default 127.0.0.1, so only your machine can reach it.
MILO_PASSWORD
Asks for a password. Set it before you expose Milo on a network.
MILO_DATA_DIR
Where milo.json lives. Default data.

FAQ

Questions

Does it send anything without me?

Not by default. Sales development starts on Review sends only, so every email, reply and meeting invite waits in Approvals. Markets starts on Review trades. Autopilot is opt-in, and SDR still escalates pricing, legal and security questions to you.

Where are my keys stored?

In data/milo.json on your machine, written so only your user can read it. A key is sent only to the vendor you entered it for. Set MILO_PASSWORD before you expose Milo on a network.

Can I use a local model?

Yes. Add an Ollama connection and choose it for Write text, for one agent or all of them. Servers that speak the OpenAI API work too, through an OpenAI connection with your own endpoint.

Is the trading real?

No. Markets reads real prices and trades from Polymarket's public API, but every position is on paper. There is no wallet, and no order is ever placed.

Can I try it without any keys?

Yes. The built-in sample-data provider answers every capability with fake companies, people, markets and model output. Switch each capability to a real connection when you are ready.

How do I add a provider?

Add a file to server/providers that exports an id, the fields it needs and a handler for each capability it supports. Milo loads it on start. docs/capabilities.md lists the arguments and results for every capability.
